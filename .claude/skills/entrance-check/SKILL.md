# 入口の点検

`data/sources.json` の県の入口を 1 件ずつ取り、47 都道府県の表を作る。見るのは「今、届くか」と「題名と鳥インフルの語があるか」だけ。

## コマンド

```
npx tsx scripts/check-entrances.ts
```

- 県の入口（約 105 件）を順に取る。同じホストへは 1.2 秒以上あけるので、数分かかる。
- 結果は標準出力に出て、`docs/entrance-check-YYYY-MM-DD.md` にも書く（同じ日の 2 回目は `-2` を付けて上書きしない）。
- 入口の一覧は `scripts/build-sources.ts` が作る。点検は一覧を読むだけで、書き換えない。
- 試すだけなら別の一覧と出力先を指定できる: `--sources <json> --docs-dir <dir>`

## 作法（変えない）

取得はすべて `politeFetch`（`functions/src/watch/politeFetch.ts`）を通す。このスクリプトの中で `fetch` を直接呼ばない。

- 名乗る。`User-Agent` は `hpai-status-map/0.1 (+公開リポジトリの URL)`。偽らない。
- 先に robots.txt を読む。禁止されている入口は取らない。
- 同じホストへの間隔は 1.2 秒以上。
- 失敗しても再試行しない。もう一度確かめたいときは、原因を考えてから 1 回だけ点検し直す。再試行ではない追加の通信が 1 つだけある。接続できず TLS の失敗と分からないときは、原因を見分けるために TLS の握手を 1 回だけ追加で試す（HEAD を 1 回。設定は変えない）。
- TLS の設定を緩めない。握手に失敗する入口は、失敗として表に出す（`rejectUnauthorized` を切るなど、回避の設定を入れない）。
- 県のドメインの外へは出ない（47 の公式のドメインとその下のホストだけ。ポートは 80、443 だけ）。リダイレクトの先も同じ決まりで止まる。
- 1 回の点検で全入口を 1 度ずつだけ取る。続けて何度も回さない。

## 結果の読み方

見出しの「確認できた県 N / 47」は、その県の入口がすべて確認できた県の数（見回りの確認済みと同じ数え方）。

| 結果の欄 | 意味と次の一手 |
|---|---|
| 確認できました | 取れた。題名と語の有無も見る |
| 確認できません（HTTP 404 など） | ページが消えた可能性。年度の切り替わりで URL が変わることが多い |
| 確認できません（古い TLS で握手に失敗: code） | サーバー側の古い設定。こちらの設定は変えない。入口ごとに扱いを決める（`docs/reachability.md`） |
| 確認できません（接続できません: code） | 一時的な失敗かもしれない。すぐに繰り返さず、時間をあける |
| 確認できません（robots.txt が禁止） | 取らない。入口の表の誤り。運営者に知らせる |
| 入口なし | その県の入口が一覧にない（今の一覧では 0 県のはず） |

- 語の有無が「なし」でも、課のトップなど平時に語がない入口がある。それだけで異常とは言えない。
- **取得できることと、県の発生を見分けられることは別。** 福岡と福井は、取得できても県の発生を見分けられる根拠がなく、国の発表で補う（設計書 §9.2、索引 Q8）。表の「確認できた」を「発生を拾える」と読み替えない。
- 今季はまだ家きんの発生がなく、発生時に常設ページや RSS が動くかは確かめられていない（`docs/data-sources.md` の「見回り先の未確認の点」）。

## 見回り先を勝手に変えない

**表に問題が出ても、`data/sources.json` や `scripts/lib/sources.ts` の入口を自分の判断で足したり消したり直したりしない。** 変更は運営者の承認が要る。

- 直したい入口があれば、どの県のどの URL を、なぜ変えたいか（点検の表の該当の行、見つけた新しい URL の根拠）をまとめて運営者に出す。
- 承認のあと、`scripts/lib/sources.ts` の表を直して `scripts/build-sources.ts` で作り直し、本番へは別の手順（`seed-sources`）で足す。
- 県のサイトを探すときも、同じ作法を守る。県のドメインの外、UA の偽装、robots.txt の無視はしない。
