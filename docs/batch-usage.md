# Batch の使い方と費用

読み取りの試験（`evals/run.ts`）と過去分の読み取り（`--backfill`）で、Claude の Message Batches API をどう使うか、いくらかかる見込みかを書く。実際に払った額は、有料の実行をした後に `docs/read-eval-log.md` へ書く。**この文書の額は、実行前の見積もりで、実測ではない。**

## 使い分け

| 用途 | 呼び方 | 値段 | 完了まで |
|---|---|---|---|
| 11/5 の合否 | `--sync`（通常の API、同時 4 件まで） | Batch の 2 倍 | 数分 |
| 比較（モデル、effort） | Batch（既定） | 半額 | 最長 24 時間 |
| 過去分（`--backfill`） | Batch | 半額 | 最長 24 時間 |

- 合否は `--sync` で行い、Batch を待たない。Batch は完了が最長 24 時間なので、結果が要る時刻の 24 時間前までに投げる。
- 依頼は主の読み手と別の読み手で 1 文書 2 件。`custom_id` は `${id}__p`、`${id}__s`（過去分は `bf<年>-<連番>__p` と `__s`）。英数字と `-`、`_` で 64 字以内。
- 1 バッチは 200MB ごとに分ける（API の上限は 256MB）。試験の 54 文書は 12.16MB なので 1 バッチ。
- バッチ ID は `data/private/eval-runs/<runId>.batches.json` に保存してから 60 秒ごとに待つ。途中で止まったら `npx tsx evals/run.ts --resume <batchId> --yes` で取り直す（新しい依頼は作らない）。
- `errored`、`expired`、`canceled` の依頼は読めなかった扱い（`read = null`、`api_error`）。読めた文書の数に入らない。
- 実際の応答（本文と引用を含む）は `data/private/eval-runs/` にだけ置く。公開してよいのは `evals/results/` の事実だけ。
- SDK の自動の再試行は切っている（`maxRetries: 0`）。失敗は再試行せず、数と理由を報告する。

## 単価（100 万トークンあたり、入力 / 出力。`shared/src/budget.ts` の値）

| モデル | 通常 | Batch |
|---|---|---|
| `claude-opus-5-5` | 4 / 20 ドル | 2 / 10 ドル |
| `claude-sonnet-5-5` | 2 / 10 ドル | 1 / 5 ドル |
| `claude-haiku-5-5` | 0.10 / 0.50 ドル（合計入力 100K 超は 0.50 / 2.50） | 半額 |

## 試験（54 文書）の見積もり

`npx tsx evals/run.ts --dry-run`（API は呼ばない）の出力。既定は主 `claude-opus-5-5`（effort medium）、別の読み手 `claude-haiku-5-5`。

| 項目 | Batch | `--sync` |
|---|---|---|
| 文書 / 依頼 | 54 / 108 | 54 / 108 |
| 合計の大きさ | 12.16MB（バッチ 1 本） | 同じ |
| 見積もり（出力 主 2,500、別の読み手 600 トークン） | 約 2.21 ドル（約 331 円） | 約 4.42 ドル（約 663 円） |
| 上限（出力が `max_tokens` 16,000 まで行った場合） | 約 9.71 ドル（約 1,456 円） | 約 19.42 ドル（約 2,912 円） |

- 入力は約 80 万トークンの概算。日本語は 1 字 1 トークン、PDF は大きさから 1 ページ 2,500 トークンで数えた上振れ側の値。キャッシュは数えていない。
- 円は 1 ドル 150 円（`DEFAULT_RUNTIME_SETTINGS.jpyPerUsd`）。
- 実際の 1 文書あたりの費用は、実行後に `summary.json` の `costPerDocumentUsd` に出る。

## 過去分（`--backfill`、索引 Q19）の見積もり

- 対象は農林水産省の月別一覧にある「疑似患畜の確認」の発表（現地調査の概要は扱わない。X-27）。出力は `data/private/backfill/<年>.json`（公開しない）。
- 件数の目安は cases.json の `related:false`: 52、25、84、11、51、24（計 247）。1 文書あたりの費用を試験の見積もり（Batch で約 0.04 ドル）と同じとすると、247 件で約 10 ドル。**これは試験の見積もりからの外挿で、実測ではない。**
- **最初に `--dry-run` で題の数を数える。合わなければ止めて報告する。** 2026-11-03 の `--dry-run`（API は呼んでいない）の結果:

  | シーズン | 数えた題 | 期待 | 結果 |
  |---|---|---|---|
  | 2025 | 24 | 24 | 一致 |
  | 2024 | 41 | 51 | **不一致**（止めて報告） |
  | 2023 | 11 | 11 | 一致（2306〜2310 の 5 か月の一覧は取れていない） |
  | 2022 | 0 | 84 | **不一致**。12 か月とも月別一覧が HTTP 403 |
  | 2021 | 0 | 25 | **不一致**。12 か月とも HTTP 403 |
  | 2020 | 0 | 52 | **不一致**。12 か月とも HTTP 403 |

  - 2023 年 10 月分までの月別一覧（`/j/press/arc/YYMM.html`）は HTTP 403 だった（取れた月は 2023 年 11 月から）。再試行も回避もしていない。国のサイトは存在しないページにも 403 を返す（`private/research/20261103-entrance-probe.md` の記録）ので、拒まれているのではなく、**この経路に古い月の一覧がない可能性が高い**（推測。確かめていない）。2024 の 41 は、題の言い回しが違うか、一覧に載らない発表があるためと推測するが未確認。
  - このため、過去分の読み取りはいまの経路では 2025 と 2023 だけが題の数と合う。2020〜2022、2024 を読むには、別の入口（国の事例一覧 PDF の発生日から個別の発表を探す、など）を決める必要がある。決めるのは利用者。

## 実行の前に

1. `--dry-run` で件数、見積もり額、大きさを出す。
2. 利用者に示して、確認を取る（支払いの上限は利用者が置く）。
3. 確認の後に `--yes` を付けて実行する。付けないと API は呼ばれない。
