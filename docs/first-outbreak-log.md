# 最初の発生の記録（手順）

今季の最初の発生が来たときに、入口ごとの最初の検知時刻を出し、事実だけを記録して見回り先を直すための手順。**いまは手順だけで、記録はまだない**（今季の最初の発生はまだ来ていない）。設計書 §9.2、§17。

## 記録するもの（事実だけ）

発生ごとに 1 つの表を作る。推測は書かない。測れないものは「未確認」と書く。

| 項目 | 取り方 |
|---|---|
| 事例（県、市町村、国内の番号） | `cases` の該当する事例 |
| 国の発表の日（時刻の記載はないことが多い） | 農林水産省の報道発表の日付 |
| 入口ごとの最初の検知時刻 | 下の手順 |
| 検知の遅れ | 最初の検知時刻と、各入口の検知時刻の差 |

## 入口ごとの最初の検知時刻

`documents` の `fetchedAt`（その文書を最初に取った時刻）と `sourceId`（どの入口で取ったか）から出す。

1. その事例に係る文書を `documents` から集める（`caseId` が事例の id のもの。確認中の事例は `rev-<documentId>`）。
2. `sourceId` ごとに `fetchedAt` の最小値を取る。これが、その入口の最初の検知時刻。
3. `sources` で `sourceId` を引き、入口の種類（`maff_press`、`maff_season`、`moe`、`pref_fixed`、`pref_rss`、`pref_press_list`）と県を表に書く。
4. 最初の検知時刻がいちばん早い入口を「最初に検知した入口」とする。
5. 検知時刻は取得した時刻で、発表の時刻ではない。発表の時刻が文書にあれば別の列に書き、取得の時刻と混ぜない。

## 見回り先を直す

- 国の発表より後にしか検知できなかった県は、`docs/data-sources.md` の入口の表と照らし、県の入口（固定ページ、RSS、報道発表の一覧）のどれで取れたかを記録する。
- 見回り先の追加や変更は、入口を直すエージェントの提案（`reviewQueue` の `entrance_proposal`）を運営者が承認して行う。この手順では `data/sources.json` を直接書き換えない。
- 取得の頻度の見直しは、`watchStatus` の失敗の記録と合わせて決める。
- 作品の価値は「速さ」ではなく、県をまたいだ全体像と整理である。速さの数字は、測った値だけを、取得の時刻であることを添えて書く。「家保より早い」とは書かない。

## 記録のしかた

- 1 発生ごとに、この文書の下に節を足す（日付、県、市町村、入口ごとの最初の検知時刻の表）。
- 原文と引用は書かない。農場名、個人名、連絡先は書かない。
