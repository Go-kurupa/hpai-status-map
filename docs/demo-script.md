# デモの台本

デモ動画の台本です。8 つの場面を、登録なしで、上から順に通します。場面 2 から 7 は、画面の試験（`web/e2e/demo-walkthrough.spec.ts`）が同じ流れを確かめています。場面 1 と 8 は語りのみで、画面の試験はありません。

## 誰の、どんな課題を、どう解決するか

動画の最初の 30 秒で、次の 3 つを言います。

- **誰の**: 冬のあいだ、鳥インフルエンザの発生を気にしている、全国の養鶏家。作者は小規模な養鶏場の当事者で、この冬、自分の農場で使う予定です。
- **どんな課題を**: 家畜保健衛生所（家保）の連絡は、県外や海外の発生まで逐一届きます。届くのは 1 件ずつの速報で、全国でどこに集中しているか、過去にどこで出たかは見えません。1 通ずつでは他人事になります。実際に近くの市で発生したとき、作者は怖い思いをしました。
- **どう解決するか**: 家保の速報を、全国の俯瞰と過去で補います。日本地図で全国の件数と自分の町の周辺の過去を見て、去年の波が近づく様子を再現で確かめ、備えを切り替えるときの確認事項と声かけ文の下書きを手に入れます。平時は点検と死亡数を記録して報告文を作れます。AI は読み取りと下書き、決まりはコード、確定は人です。

## 映さないもの

撮影の前に、画面と録画の範囲を見直します。

- 農場の正確な位置。自分の地域の場面では、地点を役場の近くのマス目にします（場面 3 の仮の地点は、作者の村の中心のマス目です）
- 働く人
- 取引先
- 発送先
- 本番の会員データ
- 鍵（API の鍵、トークン、パスワード）
- ブラウザの保存パスワードとメール

## 撮る前と撮った後の確認

1. 撮る前に、`cd web && browser-guard run -- npx playwright test demo-walkthrough` を実行します。**場面 7 が skip でないことを確かめます。** skip になるのは、舞台裏か読み取りの試験が未実測のときです。
2. 台本を 1 回通します。メールは、送信先を作者に限ります。
3. MCP の場面は、本番の接続で撮ります。
4. 撮った動画を見返して、次を確かめます。
   - 映さないものが映っていない
   - 「去年の再現です」の帯と、「仮の地点」の表示がある
   - 画面の数字が、実測か未実測かを、画面か語りで明示している
5. 本物の発生が今週あれば、再現で撮り、本物の動きは別に見せます。実在の農場の特徴には触れません。
6. 動画の長さ、提出物の一覧、提出先は、参加者ガイドで確かめます。
