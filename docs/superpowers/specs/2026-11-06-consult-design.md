# 対策の見直し相談（設計書の草案）

作成: 2026-11-06（interview-me の聞き取りから。作者の確認前の草案）

## 1. 目的

平時（シーズン前や自己点検のとき）に、養鶏事業者が「うちの鶏舎では、どの対策を先に見直すべきか」を判断する手助けをする。根拠は、集めた公的な資料と研究から作った「知見のカード」だけに限る。AI は優先順の下書きを出し、どれをやるかは本人が決める。

## 2. 当初の案から変わった点

| 当初の案（作者の発言） | 決まった形 | 根拠になった回答 |
|---|---|---|
| チャットで自分の状況や対策を相談すると、資料を元に「適している／適していない」や最適解を答える | 決まった問いに答える → 優先順の下書きリスト（各行に引用）→ 行ごとに続けて質問できる | 回答 3、4 |
| 資料は取得したものに限定（NotebookLM のように本文を渡す） | 資料を先に「知見のカード」にして、プログラムで原文と照合し、作者が確認したカードだけを使う | 回答 7、10 |
| 設計書 2026-11-03 の【決定】「文書に質問して答える機能を作らない。チャットの入口を作らない」 | この決定を覆す。大会の避ける例（基本的な RAG）に対しては、3 章の線引きで答える | 回答 1 |

## 3. 大会の避ける例に対する線引き

「資料に質問して答えるだけ」にしない。

- 入口は自由な質問ではなく、農場の条件の決まった問い。答えは、条件ごとに並べた「見直しの優先順」。
- 答えはカードだけから作る。カードは、プログラムで原文と照合し、作者が確認したものに限る（今のアプリの「読み取り → 照合 → 人の確認」と同じ考え方）。
- **画面に出す引用・資料・根拠の強さ・注意書きは、プログラムがカードのデータからそのまま出す。Claude が書いた引用は画面に出さない。** Claude が返すのは、カードの id、並び順、各行の短い理由だけ。プログラムが次を検査し、落ちた行は出さない。
  - id が実在し、確認済みのカードであること
  - 理由に、引いたカードにない数字がないこと
  - 長さと URL
- 候補のカードは、条件の答えからプログラムが決める（条件の札）。Claude が失敗したとき、予算が止まったとき、検査に落ちたときは、理由なしの並び（プログラムの順）を出す。画面が空にならない。
- 結果は「対策項目」に足して、平時の仕事につなげる。
- 人の健康、区域に入るかの断定、鶏の診断には答えない（設計書 2026-11-03 の線引きは維持）。

## 4. 使う人と入口

- **会員**（招待コードで入った養鶏事業者）: 「養鶏事業者の方」のメニューから使う。
- **審査員**: 「このサイトについて」の「審査員の方へ」から、回数の上限つきで試せる。架空の農場の条件があらかじめ入った状態で始め、結果は保存しない。
- 会員でない一般の人は使えない。

## 5. 主な流れ

1. **条件の問いに答える（10 問ほどの選択式）。** 候補は、鶏舎の造り（開放か閉鎖か）、近くの水辺・ため池・林、防鳥ネットの状態、野生動物の侵入の跡、人と車の出入り、衛生管理区域の境の作り、採卵か肉用か、飼い方、規模の幅など。問いの中身は、集めた研究の発生要因から作り、作者が確認する。農場の位置は送らない。
2. **優先順の下書きリストを受け取る。** 各行に次を載せる。
   - 見直す対策
   - なぜこの農場で先か（答えた条件とのつながり）
   - 根拠の強さ
   - 原文の引用と資料へのリンク

   海外の資料の行には「日本と飼い方が違う可能性」を添える。根拠の強さは決まった札で出す: 「義務」「発生農場の調査で見つかった不備」「研究で関係あり」「研究では効果が測られていない」「専門家の推定」「公的機関の推奨」。カードの注意書き（例「小規模な農場の研究はない」）もそのまま出す。
   - 調べて分かった根拠の穴（2026-11-06）: 小規模・平飼いの農場の研究は見つからない。ネズミ対策・防鳥ネット・車両消毒の効果を農場で測った研究も見つからない。画面でもこのとおり伝える。
3. **行ごとに続けて質問する。**「うちの場合は？」と聞くと、カードの範囲で答える（返すのは答えの文と引いたカードの id。引用はカードから出す）。カードにない問いには「集めた資料では分かりません。管轄の家畜保健衛生所にご相談ください」と答える。人の健康・区域・鶏の診断の問いは、Claude に渡す前にプログラムが語で見分けて同じ決まった文を返す。Claude が答えを拒んだときも同じ文にする。
4. **対策項目に足す。** 行ごとに「対策項目に足す」を押すと、対策項目の中の新しい欄「相談から足した見直し」に入る。本人が押したものだけが入る。

## 6. 知見のカード

- **資料の範囲（4 つとも）:**
  - 農林水産省（飼養衛生管理基準、防疫指針、発生農場の疫学調査の報告）
  - 大学・研究機関の論文
  - 都道府県・家保の資料（自己点検の表、対策のパンフレット）
  - 海外の公的機関（米国農務省、欧州食品安全機関など）
- **1 枚の中身:**
  - 対策
  - 効く条件（どんな農場に当てはまるか）
  - 根拠の強さ（調査の種類）
  - 原文の引用
  - 資料名
  - URL
  - 取得日
  - 国内か海外か
- **作り方:**
  1. 調査役が資料を集める。
  2. Claude がカードの下書きを作る。
  3. プログラムが、引用が原文にあるかを照合する（今の `shared/src/read/quote.ts` を使い回す）。
  4. 作者が HTML の一覧で「使う／外す」を決める。
- **使うときの持たせ方:** 確認済みのカードの全部を system に置き、プロンプトキャッシュを効かせる（カードは数十枚で、全部を一度に渡せる量の見込み。推測）。

## 7. 保存と権限

- 対策項目に足した見直しは、農場ごとに保存し、その農場の会員だけが読める（今の死亡・消毒の記録と同じ規則）。保存するのはカードの id、足した日時、足した人だけ（自由な文は保存しない）。
- 相談の条件と答えそのものは、既定では保存しない（AI の既定案。保存するかは未決）。
- 審査員の入口の相談は保存しない。

## 8. 費用

- モデルは Claude Opus 5.5 を既定にする（今のアプリの読み取りと同じ）。
- 1 回の相談（リスト 1 回）の見込み: カードの入力 約 1.5 万トークン（キャッシュで大半が 1/20 の料金）＋出力 約 2 千トークンで、約 0.05〜0.1 ドル（推測。実測して直す）。
- 今の費用の止め線（月 10,000 円）と 1 日の上限の仕組み（`functions/src/drafts/dailyLimit.ts`）に乗せる。審査員の入口は、1 日の回数を別に絞る。

## 9. 動画

S6 の「作品の中の Claude」で、約 10 秒見せる。「読み違い 0 件」の後に、同じ「引用を原文と照合する」考え方で相談に答える場面を置く。実演の 3 つはそのままにし、作り方の場面を縮める（回答 11）。台本と絵コンテの直しは、動画のセッションへ渡す。

## 10. 受入条件（案）

- 条件の問いに答えると、優先順のリストが出る。各行に引用とリンクがあり、引用は確認済みのカードの原文と一致する。
- 引用が合わない行は表示されない（試験で、引用を書き換えた応答を入れると、その行が消える）。
- カードにない問いには「分かりません、家保へ」と答える。人の健康、区域、診断の問いにも答えない（試験の問いの組で確かめる）。
- 「対策項目に足す」を押すと、対策項目の新しい欄に入る。他の農場や会員でない人からは読めない（権限の試験）。
- 審査員の入口から、架空の農場で試せる。回数の上限に達すると、その旨を出して止まる。
- 費用の止め線を越えると、相談は止まり、そのことを画面に出す。

## 11. 決定（作者の回答、2026-11-06）

| # | 決定 |
|---|---|
| 1 | 提出に含める。小さくではなく、しっかり実装する |
| 2 | 場面は平時の対策の見直し |
| 3 | 答えは優先順の下書きリスト＋行ごとに続けて質問できる |
| 4 | 条件は決まった問い（選択式）で伝える |
| 5 | 資料は 4 種類すべて |
| 6 | 使えるのは会員と、審査員の入口（回数つき） |
| 7 | 資料は知見のカードにして持たせる |
| 8 | 結果は対策項目に足せる |
| 9 | カードにない問いは「分からない」と答え、家保へ案内する |
| 10 | カードは照合に通った後、作者が一覧で確認してから使う |
| 11 | 動画は S6 の作品の中の Claude で約 10 秒 |
| 12 | 相談の機能は削らない。間に合わないときは、画面の仕上げなど他の作業を詰める |
| 13 | カードは自由に使える資料だけから作る（農水省・岡山県の PDL1.0、CC BY の論文、英国の OGL、米国政府の資料）。無断転載不可・非営利のみ・改変不可・利用条件の記載なしの資料は使わない |

## 12. AI の既定案（作者の再承認は求めない細部）

- メニューの名前は「対策の見直し相談」（仮。画面の見本で確かめる）。
- 対策項目の中に「相談から足した見直し」の欄を新しく作る（今の対策項目には足す仕組みがないため）。
- モデルは Opus 5.5、カードは system に置いてキャッシュする。
- 相談の条件と答えは保存しない。

## 13. 未決（作者に聞く）

- **出典の表示（決定 13 の続き）:** 行の文はカードを要約したもので「加工」に当たる。PDL1.0 は出典と「加工して作成」、CC BY は帰属と変更の表示、OGL v3.0 は決まった帰属の文が要る。画面の資料の行、`docs/data-sources.md`、README に入れる。
- **全部の引用の照合:** 抜き取り 56 件は一致（本体、2026-11-06）。残りは、作品の名前で原本を取り直して quoteExists で照合するスクリプトで全件確かめ、結果（`verified` と SHA-256）だけを公開する。確認済みのカードがすべて照合済みであることを試験にする。
- **審査員の入口:** ログインなしで自由な文を受けるので、架空の農場の条件はサーバーで固定し、1 日の全体の回数を取引で数えて低く絞る。入力はログに残さない。公開前に security-reviewer で点検する。
- **遅さ:** Opus 5.5 は常に考えるので、1 回の時間を本物の呼び出しで 1 回測ってから画面を作る（有料、約 10 円。作者の了承が要る）。
- **条件の問いの中身:** 調査の後に作者が確認する。
- **相談の画面の見た目:** 見本の HTML で確かめる。
- **日程:**

  | 日 | やること |
  |---|---|
  | 11/6 夜 | 調査 |
  | 11/7 | カードの作成と作者の確認（約 1 時間、推測）、実装、試験 |
  | 11/8 | 撮影と提出 |

  11/7 は共同経営者の確認や UI の作業と重なる。遅れても相談の機能は削らず、他の作業を詰める（決定 12）。
