# 鳥インフル発生状況マップ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 全国の養鶏家が冬のあいだ毎朝開く、発生の地図と記録の道具を作り、2026-11-08 20:00 JST までに「Built with Claude: Japan 2026」のテーマ 1 へ提出する。作者もこの冬、自分の農場で使い続ける。

**Architecture:** 国、47 都道府県、環境省の発表を Cloud Functions が Claude を使わずに見回り、新しい文書だけを二つの Claude が独立に読み、プログラムが照合して Firestore に載せる。段階、解除の見込み、死亡率、宛先、確認リストは決まりとしてコードで作り、純粋関数は `shared/` で画面とサーバーが共用する。画面はデータの口を通すので、本番、再現、見本の農場が同じ画面で動く。公開 API、MCP、入口を直すエージェントも Cloud Functions に置く。

**Tech Stack:** Node 24、TypeScript、Firebase（Hosting、Cloud Functions 第 2 世代 `asia-northeast1`、Firestore、Cloud Storage、Authentication）、Vite、React、MapLibre GL JS、地理院タイル、N03、Turf.js、`@anthropic-ai/sdk`、Claude Managed Agents、MCP SDK、Nodemailer、Vitest、Playwright。版は F-01 で exact に固定する。

**Spec:** docs/superpowers/specs/2026-11-03-hpai-status-map-design.md

## Global Constraints

- 設計、実装、レビューは Claude Code だけで完結する。Codex もローカル LLM も使わない（§12）。
- 成果物は期間中に新しく作ったものだけにする。既存アプリのコード、画面、データ構造を持ち込まない。
- 公開リポジトリとして扱う。秘密の値、農場の所在地、社名、家保の連絡先、個人名、メールアドレス、`private/` の内容を書かない。
- commit と本番の deploy は利用者の確認の後。deploy は `--only`、`--account`、`--project` を付ける。push と公開も利用者の確認の後。
- 作品の価値は「全体像、過去の発生、記録、近隣への説明」と説明し、「家保より早い」と言わない（§1）。やることはリマインドにとどめる（§7）。
- 「近くに何もない＝安全」と読める表示をしない。区域の内外を断定しない。「区域の外です」「安全」「安心」と書かない（§2、§15）。
- 区域内の義務を区域外の人に義務として見せない。平時の義務を「義務ではない」と見せない（§2）。
- 農場を点で示さない。区域の図の円から農場の位置を割り出さない（§2）。
- サーバーに保存する位置は約 1km のマス目（3 次メッシュ）まで。正確な地点は端末からも送らない（§12）。
- 農場のデータは会員の uid に限る。死亡数や羽数は他の農場からも運営者の画面からも見えない（§12）。
- 発生農場の不備を事例や市町村と結びつけない。全国の傾向だけを示す（§2）。
- 県の発表の文章を転載しない。公開するのは事実（日付、市町村、羽数）とリンクだけ。報道機関と X を取り込まない（§2）。
- 文書に質問して答える機能とチャットの入口を作らない。防疫の判断と人の健康の質問に AI が答えない。診断をしない（§2）。
- 家保への報告を自動で送らない。人が確かめて自分で出す（§2）。
- 自治体と連携しない。住民へのメールを作らない。メールは招待コードの会員の農家だけ（§2、§6）。
- 段階は ①〜④。距離は地点のメッシュの中心から発生市町村の面までの最短距離に 0.85km を足す。基準は 10km で、複数の半径は最も外側を使い、10km より狭くしない（§5）。
- ①は移動制限区域の解除まで続ける。監視強化区域は段階に数えない（§5）。
- 否定は人が確かめてから消す。受け取った全員へ訂正を送る（§6、§10.2）。
- メールは①がすぐ、②③が朝 6 時、④は送らない。確認中は同じ県の会員へすぐ。同じ会員に同じ事例の同じ出来事を二度送らない。朝は 1 通にまとめ、何もない日は送らない（§6）。
- 見回りは Claude を使わず、シーズン中は 1 時間ごと、1 周 3 時間以内。名乗りを付け、robots.txt に従い、同じサイトへの間隔を 1.2 秒以上あける。UA の偽装などの回避をしない（§9.1）。
- TLS の検証や再交渉を黙って緩めない。届かない県は「確認できません」にして国の発表で補う（§9.7、契約 3.7）。
- 読み取りの主は `claude-opus-5-5`、別の読み手は `claude-haiku-5-5`（試験に通らなければ `claude-sonnet-5-5`）。一致の判定はプログラムが行う（§9.4）。
- 必須の項目（都道府県、市町村、段階、日付）がすべて合格し二重読みと一致すれば自動で載せる。読み取りの試験に通るまでは全件を確認中で運用する（§9.5）。
- 区域、段階、解除の見込み、死亡率、誰に送るか、確認リストはコードで作り、Claude に判断させない（§13）。
- 死亡率は告示の定義（同じ家きん舎で 1 日の死亡率が対象期間の平均の 2 倍以上。対象期間は当日から遡って 21 日間）で計算する（§8）。
- 読めなかった県を地図で区別し、「47 都道府県のうち N 件を確認、M 件は確認できていません（県名）」と時刻を常に出す（§9.7）。
- すべての画面に「いつ時点か」を出す。再現と見本の農場には「去年の再現です」の帯を出す（§15）。
- 過去の発生は 6 シーズンで 247 事例（52、25、84、11、51、24）。事実として出し、予測しない（§4、§11、§16）。
- 入口を直すエージェントは提案だけを行い、運営者が承認する。自由な Web 検索と Web fetch を使わず、同じ県のドメインに限る（§13）。
- 公開 API と MCP は読み取り専用、認証なし、回数を制限する。農場のデータとメッシュを扱わない（§14）。
- 運用の費用は月 3,000 円まで。月 2,000 円で進捗報の読み取りを止め、2,500 円で読み取りを止める。止めても検知、国の定型文の読み取り、確認中の表示は動く（§15）。
- N03 の測量法の手続きの要否は原本から読み切れない。要らないと確認したとは書かない。回答が間に合わなければ、明記された CC BY 4.0 に従って公開し、判断を README に書く（§10.3）。
- 数字で効果を言うときは実測した値だけを使う。削減時間は測っていないので言わない（§16）。
- 秘密の値は利用者が直接設定し、会話に出さない（§12、§22）。
- 落とす順は「日程と判断点」の落とす単位のとおり（§18）。

## Review Focus

試験されにくく、人が困りやすい入力や失敗を、人が困る順に並べた。試験は担当タスクの本文にある。レビュアーはこの行の点を見る。

1. **県をまたぐ未読み込み**（担当: F-07、W-03、M-02、M-03、M-13）。隣の県の発生を冷えた状態で計算すると、朝のメールが止まるか `/todo` が落ちる。発生の日に知らせと確認リストの両方を失う。見る点: `fakeGeo` が未読み込みで投げるか、全呼び出し元に `ensurePrefs` があるか。
2. **メールの送信の失敗**（担当: M-02、M-13、I-07）。Gmail の 1 日 500 通の制限やアプリパスワードの失効で全件が落ちる。運営者へのメールも同じ Gmail なので、気づく手段は運営者の画面の `mail_failing` だけである。見る点: `failed` の `morning` が送り直され否定の訂正が落ちないか、認証と上限のエラーで連打しないか、すぐの知らせ、朝のまとめ、送り直しのどの経路でも `mail_failing` が 1 日 1 件入るか。
3. **確認中のメールの連続と配信停止**（担当: M-02、M-04、M-13）。同じ県に確認中のメールが続くと会員が配信を止める。同じリンクで死亡率の基準の知らせも止まるので、知らせの量が通報の遅れにつながる。見る点: 通数の実測が `docs/mail-operation.md` にあるか、止めた会員の記録の画面に常に出るか。上限は Q3 で決める。
4. **読めない県が読めたように見える**（担当: I-02、I-18、W-06）。200 で中身が別物（メンテナンス、ブロック、トップへの転送）の県が「何もない」に見え、エージェントの対象（`failingSince`）にもならない。見る点: 語の消失と転送が失敗に数えられ `summarizeWatch` まで届くか、見回り全体が止まっても `reconcileNational` が気づくか。
5. **死亡数の入力の抜けと誤り**（担当: M-07、M-04、M-05、F-05、M-13）。人の通報に直接関わる。記録のない日を飛ばして最大 120 日まで遡るので、数か月前の平均と比べて「当たらない」と出ることがある。文字や負の数、羽数を超える値は計算を壊す。見る点: `invalid_input` が黙って当たらない扱いにならないか、遡った日数が出るか、ルールと画面の両方で入力を止めるか、家保の連絡先が未登録でも設定への案内が出るか。
