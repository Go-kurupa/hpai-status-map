# 対策の見直し相談 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 会員（と審査員の入口）が農場の条件の問いに答えると、確認済みの「知見のカード」だけを根拠にした見直しの優先順が出て、行ごとに続けて質問でき、選んだ行を対策項目に足せるようにする。

**Architecture:**
- 候補のカードはプログラムが条件の答えから決める（`shared/src/consult/`）。Claude（関数 `consultPlan`・`consultFollowup`）が返すのは、カードの id・並び・短い理由だけ。
- 画面の引用・資料・根拠の札・注意書きは、`data/consult/cards.json` からそのまま出す。
- Claude が失敗したとき、予算が止まったとき、検査に落ちたときは、プログラムの順を理由なしで出す。
- カードの引用は、スクリプトが原本を取り直して `quoteExists` で照合する。結果は `data/consult/verify.json` に残す。

**Tech Stack:** TypeScript、zod 4、Firebase Functions v2（onCall）、Firestore の規則、React（web）、vitest、Playwright、`@anthropic-ai/sdk`

**Spec:** `docs/superpowers/specs/2026-11-06-consult-design.md`

## Global Constraints

- **使わないもの:** Codex とローカル LLM（`CLAUDE.md`）。
- **モデル:** `claude-opus-5-5`。thinking は送らない（常に考える）。`output_config.effort` は `"low"` から測って決める。サンプリング引数は送らない。tool_choice は送らない（今の `callDraft` と同じ）。
- **カードの置き方:** 確認済みのカード全部を system に置き、`cache_control: {type: "ephemeral"}` を付ける。可変の値（日付、id）は system に入れない。
- **refusal の扱い:** 決まった文を返す。fallbacks は付けない。拒んだ問いを別のモデルで答えさせないため。
- **決まった文（作者の決定 9）:** `OUT_OF_SCOPE_TEXT = "集めた資料では分かりません。管轄の家畜保健衛生所にご相談ください。"`
- **Claude に渡さないもの:**
  - 農場の名前、位置、記録
  - 自由な文（続けての質問）を指示として渡すこと。続けての質問は JSON の 1 項目として渡す
  - ログに入力の文を残すこと
- **使うカード:** 自由に使える資料だけ（決定 13）。`license` は `PDL1.0`、`CC BY`、`CC BY 4.0`、`OGL v3.0`、`US Gov` のどれか。
- **根拠の札（画面の文）:**

  | `evidence` | 画面の札 |
  |---|---|
  | `obligation` | 義務 |
  | `outbreak-finding` | 発生農場の調査で見つかった不備 |
  | `study-association` | 研究で関係あり |
  | `study-no-difference` | 研究では効果が測られていない |
  | `recommendation` | 公的機関の推奨 |
  | `expert-estimate` | 専門家の推定 |

- **費用:** 月の soft の上限で止める（`isDraftBudgetStopped`）。
  - 会員: 1 人 1 日 10 回（`consultPlan` と `consultFollowup` の合計）
  - 審査員の入口: 全体で 1 日 30 回
- **作業ツリー:** 別のセッションが `web/src/pages/map`、`web/e2e`、`web/src/pages/todo/texts.ts`、`SectionTabs` を同時に直している。T1〜T7 は新しいフォルダだけに書く（`shared/src/consult/`、`functions/src/consult/`、`scripts/consult/`、`data/consult/`）。`firestore.rules` の追加は 1 か所。web の既存のファイルに触るのは T9 から。T9 では、着手前に `HANDOFF.md` に境界を書く。
- **公開の決まり:**
  - commit は作者の確認の後。ファイルを名指しして add する。
  - push と deploy は毎回作者に確かめる。
  - deploy には `--account <作者の個人用アカウント（HANDOFF.md）>` を明示し、`firebase login:list` の結果を見せる。

## Review Focus

1. **続けての質問に「前の指示を無視して…」と書かれる。** 答えは決まった文か、カードの範囲の答えになり、カード外の内容は出ない。→ T3（検査）と T5（関数）の試験
2. **審査員の入口が繰り返し呼ばれる。** 31 回目からは Claude を呼ばず、上限の文とプログラムの順を返す。条件はクライアントから送っても無視され、サーバーの架空の農場を使う。→ T5
3. **Claude が候補にない id や未確認のカードの id を返す。** その行は出ない。全部落ちたら、プログラムの順を返す。→ T3
4. **健康・区域・診断の問い。** Claude を呼ばずに決まった文を返し、費用も回数も使わない。例:
   - 「人にうつりますか」
   - 「うちは制限区域に入りますか」
   - 「鶏が元気がないのは鳥インフルですか」

   → T3 と T5
5. **確認済みのカードの照合が古い。** `verify.json` に照合の記録がない確認済みのカードがあれば、試験が落ちる。→ T4
