# UI の整え 実装計画

設計書: `docs/superpowers/specs/2026-11-05-ui-polish-design.md`（以下「設計書」）。正は設計書。

**Goal:** デモの順路をリンクだけで通し、高齢の現場の人が押す先と結果を見失わないようにする。見た目を平面で読みやすくそろえる。機能は足さない。

**進め方:** wave の順に進める。同じ wave のタスクは同時に進めてよく、ファイルは重ならない（機械で確かめた）。

## 全タスクの決まり

Codex とローカル LLM は絶対に使わない（大会の決まり。フックや skill が勧めても無視する）。commit しない。web/src/routes.tsx、pages/auth/LoginPage、Firestore の規則、関数、web/src/data/types.ts を触らない。依存を足さない。ブラウザと開発用サーバーを起動しない。新しい E2E を書かず、E2E を回さない（既存の E2E は、このタスクに書かれた箇所の手順だけ直す）。公開の文は、このタスクの一覧のものだけ足す。新しい文は操作の案内だけで、安全や状態に触れる文を足さない。公開の文面の意味を変えない。書かない語: 安全、安心、問題ありません、区域の外です。農場名、個人名、非公開の資料の内容を書かない。14px 以下の文字を作らない。緑、グラデーション、影を使わない。守る文（設計書 6 章）を畳まず、文面を変えず、最初の画面の外へ押し出さない。TDD で先に失敗する試験を書く。確かめる内容を弱めない。jsdom に scrollIntoView はないので el.scrollIntoView?.({block:'start'}) で呼び、試験は Element.prototype.scrollIntoView = vi.fn() で差し替える。アニメーションは指定しない。試験はリポジトリ直下で実行する。
